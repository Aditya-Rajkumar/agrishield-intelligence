# AgriShield Intelligence - Agent Context

## Project summary

AgriShield Intelligence (also branded in the UI as AgriShield AI) is a responsive agricultural decision-support web app. It combines NASA Earth-observation climate data with a farmer-editable profile to explain recent field conditions, screen for climate risks, compare crop rotations, and explore NASA satellite imagery. It is an informational tool, not a substitute for local agronomic advice or a source of guaranteed predictions.

The initial demo farm is in Nashik, Maharashtra, India (19.99, 73.79). Farm location, soil, crop, water availability, area, and irrigation settings are shared across pages and saved in browser local storage.

## Technology and runtime

- React and TypeScript, built with Vite.
- TanStack Start and file-based TanStack Router for server rendering and routes.
- TanStack Query for fetching and caching climate data.
- Tailwind CSS, reusable UI components, and Lucide icons.
- Leaflet for maps; Recharts for climate charts.
- Nitro builds the server bundle for the Cloudflare module preset.

Install dependencies with `bun install` (the repository lockfile is `bun.lock`). Useful commands:

- `npm run dev` - start the local development server.
- `npm test` - run Vitest.
- `npx tsc --noEmit` - type-check the project.
- `npm run build` - verify the production build.

## Application routes

- `/` - Dashboard metrics, NASA POWER climate charts, rule-based risk summary, recent-observation alerts, farm map, and data status.
- `/farm` - Farm location and profile editor, environmental summary, and selectable NASA GIBS imagery overlays.
- `/climate` - Historical temperature, precipitation, and solar-radiation analysis.
- `/crops` - Crop and rotation screening based on climate, soil, water, and user priorities; includes an experimental yield-screening calculator.
- `/risk` - Rule-based drought, excess-rainfall, heat, water-availability, and soil risk indicators with evidence.

`src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it manually; add route files under `src/routes/` and let the router plugin regenerate it.

## Data flow and domain logic

1. `src/lib/farm-context.tsx` provides the shared farm profile and `useFarmClimate`.
2. `src/lib/nasa/queries.ts` defines the 90-day query window and caching.
3. `src/lib/nasa/power.functions.ts` fetches NASA POWER data server-side. If `AGRISHIELD_API_URL` is configured, it calls that Python backend instead; the backend must return the `ClimateSeries` shape in `src/lib/nasa/types.ts`.
4. Route components derive display values through pure functions in `src/lib/agri/`.

NASA POWER daily variables currently include `T2M`, `T2M_MAX`, `T2M_MIN`, `RH2M`, `PRECTOTCORR`, and `ALLSKY_SFC_SW_DWN`. POWER data is historical and can lag by several days. Missing-value sentinels must remain missing (`null`), not be replaced with plausible-looking measurements.

`src/lib/nasa/gibs.ts` defines NASA GIBS tile layers used by the farm map. The map's base layer uses OpenStreetMap; preserve its attribution and NASA imagery attribution.

## Important implementation rules

- Never invent or mock NASA observations. Preserve source, observation dates, units, missing values, loading states, and explicit error states.
- Keep historical observations distinct from forecasts. Do not describe an observation as something expected in the future.
- Keep agricultural calculations and rules pure in `src/lib/agri/`; keep reusable presentation components in `src/components/app/`; keep route-level data orchestration and page layout in `src/routes/`.
- The alert center reports only thresholds that can be assessed from available recent observations. Missing measurements must not result in a false all-clear.
- Yield output is an experimental climate-screening estimate, not a validated yield model or full-season forecast. It requires user-supplied crop parameters and complete observed inputs; never imply that the result is guaranteed.
- Keep API calls and secrets out of browser code. Use the existing server function/backend boundary for climate data.
- JSX belongs in `.tsx` files. Adding a component or utility alone does not display it; import and render UI components from a route.
- Surface fetch and rendering failures instead of silently substituting defaults or success-shaped data.
